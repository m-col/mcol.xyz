      1 haskell study: pointfree rules, and the blackbird
      2 =================================================
      3 
      4 :date: 2021-09-30
      5 :summary: haskell study: pointfree rules, and the blackbird
      6 
      7 Since I started learning Haskell (not too long ago) it was never really clear
      8 to me the benefits of writing functions in a pointfree style. It seemed that
      9 doing so for relatively simple functions that would require minimal changes
     10 made sense, such as the example from the Haskell `pointfree wiki page`_:
     11 
     12 .. code-block:: haskell
     13 
     14    sum xs = foldr (+) 0 xs
     15    -- and pointfree:
     16    sum' = foldr (+) 0
     17 
     18 Here, all it takes to make the function pointfree is omitting the argument.
     19 Doing so removes some visual noise but it otherwise looks identical.
     20 
     21 The thing is, this small change -- omitting the arguments while keeping the
     22 rest unchanged -- is often not the only thing required to rewrite a function in
     23 a pointfree form. For this reason I haven't had much drive to use pointfree
     24 style for most functions that I write.
     25 
     26 What changed my mind was Amar Shah's articles titled `Point-Free or Die`_ (and
     27 `YouTube video`_). I won't repeat
     28 things from there (much) but I highly recommend reading those articles or
     29 watching the video.
     30 
     31 While all of what he says is really interesting and worth reading, the crux of
     32 the matter is that one can learn to recognise common function shapes so that
     33 writing them in a pointfree style simply involves using something to map a
     34 concise pointfree form to that shape. The blackbird (or B1) combinator is the
     35 'something' that Amar identifies as what he needs to write his function in a
     36 clear and elegant way:
     37 
     38 .. code-block:: haskell
     39 
     40    blackbird :: (c -> d) -> (a -> b -> c) -> a -> b -> d
     41    blackbird f g x y = f (g x y)
     42 
     43 The shape taken by a function that would make use of the blackbird is a
     44 function that takes two arguments (:code:`a` and :code:`b` above) and inputs
     45 these into one function and pipes the output of that into another function.
     46 Without using this combinator, the pointfree version is otherwise left in this
     47 more obscure form:
     48 
     49 .. code-block:: haskell
     50 
     51    func :: a -> b -> d
     52    func = (f .) . g
     53 
     54 While one could argue that bringing another object into the mix complicates
     55 things further, being aware of this and `other such combinators`_ means that
     56 when familiar shapes appear in your functions there is a go-to combinator in
     57 your toolbox to represent that shape. Together, these combinators account for a
     58 wide variety of function shapes, letting us write many more functions elegantly
     59 in pointfree style with only a little extra work.
     60 
     61 Plus, isn't it pretty?:
     62 
     63 .. code-block:: haskell
     64 
     65    (.:) = blackbird  -- A common blackbird infix operator
     66    func = f .: g
     67 
     68 .. _`pointfree wiki page`: https://wiki.haskell.org/Pointfree
     69 .. _`Point-Free or Die`: https://amar47shah.github.io/posts/2016-08-28-point-free-part-2.html
     70 .. _`YouTube video`: https://www.youtube.com/watch?v=seVSlKazsNk
     71 .. _`other such combinators`: https://hackage.haskell.org/package/data-aviary-0.4.0/docs/Data-Aviary-Birds.html
