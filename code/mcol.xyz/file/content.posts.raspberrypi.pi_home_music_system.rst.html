      1 music that follows you around the house: part 1. streaming to multiple players
      2 ==============================================================================
      3 
      4 :date: 2019-09-21
      5 :summary: music that follows you around the house: part 1.
      6 
      7 Often when I come across an amazing new record I'll play it on repeat all day,
      8 every day for a week or two. My laptop's speakers are pretty decent, but
      9 unfortunately they don't levitate nearby as I move around my home. Though that
     10 is a problem I don't intend to solve, I figure the next best thing is have one
     11 device stream music all around my home, but have it playing only in the room
     12 that I am in.
     13 
     14 This post is the first step on the way to set up this system. The aim for the
     15 final setup is to have three parts:
     16 
     17 * A central music server that has local access to my music library.
     18 * Playback clients that, when somebody is in the room, play the music through connected speakers.
     19 * Control clients that use the `MPD protocol
     20   <https://www.musicpd.org/doc/html/protocol.html>`_ to control playback from
     21   any other device on the network (i.e. PCs and phones).
     22 
     23 I opted to use Raspberry Pis for the server and playback clients, for ease of
     24 use and low energy consumption. By the end, playback clients will (hopefully)
     25 be able to fully disconnect their speakers from the power when they are not
     26 playing.
     27 
     28 
     29 the music server
     30 ----------------
     31 
     32 Starting with a pi that we can access over SSH, we need to give it access to
     33 our music library (remember to stick the storage disk into :code:`/etc/fstab`
     34 with auto-mounting) and install mpd:
     35 
     36 .. code-block:: bash
     37 
     38     apt-get install mpd
     39 
     40 Next, we need to configure mpd to stream its music throughout the local
     41 network. There are a number of ways to do this, each with their pros and cons.
     42 The most straightforward method is to use mpd's built-in httpd server.
     43 
     44 To enable this, we need to add the following settings to :code:`/etc/mpd.conf`
     45 (or alternatively :code:`$HOME/.config/mpd/mpd.conf`):
     46 
     47 .. code-block:: bash
     48 
     49     music_directory "/path/to/music"
     50     db_file         "/path/to/database"
     51     log_file        "syslog"
     52     state_file      "/path/to/state_file"
     53 
     54     audio_output {
     55         type        "httpd"
     56         name        "Raspberry Pi Music Server"
     57         encoder     "flac"
     58         format      "44100:16:1"
     59         always_on   "yes"       # Stay connected to clients when music stops
     60         tags        "yes"       # Also stream tags
     61         port        "8000"
     62         max_clients "0"         # Allow unlimited clients
     63     }
     64 
     65     bind_to_address "any"   # allow remote access
     66     port            "6600"
     67     restore_paused  "yes"
     68     auto_update     "yes"
     69     user            "pi"    # run as user rather than root
     70 
     71 This configuration makes mpd output audio via http on port 8000. Playback
     72 clients can then listen in on this stream and play it on connected speakers.
     73 
     74 On port 6600 we have the usual mpd protocol communication with the server,
     75 which we can use to control music playback.
     76 
     77 I've used :code:`encoder "flac"` for lossless streaming, though other options
     78 can be used (`described here
     79 <https://www.musicpd.org/doc/html/plugins.html#encoder-plugins>`_).
     80 
     81 mpd is packaged with a systemd service that works well to manage its process
     82 and logging. By using :code:`user "pi"` above we can take advantage of the
     83 preconfigured sandboxing settings in this service by enabling it as is, before
     84 the process is transferred to a non-root user. Enable it with:
     85 
     86 .. code-block:: bash
     87 
     88     systemctl enable --now mpd.service
     89 
     90 If we didn't use :code:`/etc/mpd.conf` and instead wanted to use a different
     91 config file, we must change this line in :code:`/etc/default/mpd` to add the
     92 config's path:
     93 
     94 .. code-block:: bash
     95 
     96     MPDCONF=/etc/mpd.conf
     97 
     98 Now on to the clients.
     99 
    100 
    101 playback clients
    102 ----------------
    103 
    104 mpd also works great for playing back http streams, so my playback clients are
    105 also all Raspberry Pis with the mpd service enabled.
    106 
    107 However, on these guys we need to configure the mpd config differently:
    108 
    109 .. code-block:: bash
    110 
    111     bind_to_address "127.0.0.1"
    112     log_file        "syslog"
    113     state_file      "/path/to/state_file"
    114 
    115     audio_output {
    116         type        "alsa"
    117         device      "hw:0,0"
    118         name        "speaker"
    119     }
    120 
    121     restore_paused  "no"
    122     auto_update     "no"
    123 
    124 We don't need remote access to mpd on these clients, as they just relay
    125 whatever is being played from the main server. As we aren't managing a library
    126 with this mpd instance we don't need to specify any paths for the music
    127 directory or database. For this same reason we don't need to enable
    128 auto_update. We also don't want to restore mpd into a paused state, because we
    129 want to use only the main server to control playback.
    130 
    131 With this audio_output configuration, music is output through the headphone
    132 jack using alsa and out to speakers.
    133 
    134 To make these clients listen to the http stream coming from the main server,
    135 simply add its URL to the client's playlist and enable repeat. We can do this
    136 using mpc:
    137 
    138 .. code-block:: bash
    139 
    140     apt-get install mpc
    141     mpc repeat 1
    142     mpc add http://<server ip address>:8000
    143 
    144 Now they'll stay connected to the http stream, playing it non-stop, so pausing
    145 the main server's mpd pauses playback by all clients.
    146 
    147 control clients
    148 ---------------
    149 
    150 These clients are other devices we have on the network that we want to use to
    151 control playback, such as phones or laptops. To do this, we communicate with
    152 the main server using the MPD protocol to tell it what to do. Changes to
    153 playback are propagated to the playback clients that are listening in on the
    154 http stream.
    155 
    156 To control the music, we simply need an mpd client pointed at the music serving
    157 pi. My favourite client is ncmpcpp, which can be installed from most distro
    158 package managers onto your PC. Using these arguments we can control the server:
    159 
    160 .. code-block:: bash
    161 
    162     ncmpcpp --host <server ip address> --port 6600
    163 
    164 I have not yet tested out many mpd clients so I will save that for a later
    165 post. ncmpcpp is great for controlling the music from my PC, but if guests
    166 wanted to control the music then a web interface served up from the main
    167 raspberry pi might be a more convenient way for them to control it.
    168 
    169 With the playback clients listening to the http stream, when we start playback
    170 from the main server and if we haven't had any bad luck then we should be
    171 hearing the music play!
    172 
    173 If you don't hear anything playing from the pi's speakers, try with this line
    174 added to :code:`/boot/config.txt`:
    175 
    176 .. code-block:: bash
    177 
    178     dtparam=audio=on
    179
