      1 extend ranger file manager with git bindings
      2 ============================================
      3 
      4 :date: 2019-06-02
      5 :summary: extend ranger file manager with git bindings
      6 :modified: 2020-08-02
      7 
      8 This is a small but incredibly useful adjustment to the default configuration
      9 that ships with `ranger <https://github.com/ranger/ranger>`_.
     10 
     11 If you have never used ranger, it is a fast terminal file manager with a boat
     12 load of useful features out of the box. You can likely get it from your
     13 distro's repos.
     14 
     15 One of the features it is missing, however, is functional git bindings that you
     16 can use to manipulate your local git repositories.
     17 
     18 On the upside, ranger is highly customisable, so these features can simply be
     19 added into the config at :code:`$HOME/.config/ranger/rc.conf:`
     20 
     21 .. code-block:: conf
     22 
     23     map bs shell git -c color.status=always status | less -r
     24     map bp shell git push | less -r
     25     map bl shell git pull | less -r
     26     map bd shell git diff --color=always %s | less -r
     27     map bD shell git diff --color=always | less -r
     28     map ba shell git add %s
     29     map bA shell git add -f %s
     30     map bu shell git restore --cached %s
     31     map br shell git restore %s
     32     map bm console shell git commit -m '
     33     map bc console shell git checkout%space
     34 
     35 The second column is our keyboard bindings. By default the 'b' prefix is
     36 unused, so we can stick all git-related commands to this prefix. The third
     37 column we either have :code:`shell,` which executes the following text, or
     38 :code:`console,` which types out the following text on ranger's command line.
     39 
     40 The first 5 lines pipe output into :code:`less`. If we didn't do this then
     41 ranger would steal the screen again and we wouldn't see the output from the
     42 command. The :code:`-r` option preserves any colour in the output from the git
     43 command when presented in less. :code:`git status` is a bit of a weird one; I
     44 found that it needed the :code:`-c color.status=always` to output color codes,
     45 but this seemed to be inconsistent across git versions.
     46 
     47 Some commands contain :code:`%s`; in these lines the current file is
     48 substituted, allowing us to interactively move around our repository
     49 git-diffing or git-adding individual files as we need. Super useful!
     50 
     51 The final two lines pre-fill ranger's command line so you can the continue your
     52 commit or checkout command before executing it.
     53 
     54 Of course, these are just the bare minimum for integrating git bindings into
     55 ranger. Depending on your git workflow requirements you can extend or customise
     56 these so you can glide around and play with your repos with ease.
     57 
     58 For example we can add a quick shortcut to check out tig for a closer look at
     59 the commit history:
     60 
     61 .. code-block:: python
     62 
     63     map bt shell tig
     64 
     65 Let me know if you use similar bindings or extend these and have found some
     66 cool tricks!
