      1 interactive Mac-like workspace swiping for Qtile
      2 ================================================
      3 
      4 :date: 2022-11-07
      5 :summary: Implementing interactive Mac-like workspace touchpad swiping for
      6           Qtile
      7 
      8 I recently added support for the wlroots :code:`wlr_pointer_gestures_v1`
      9 protocol to Qtile's Wayland backend, primarily to relay multi-finger touchpad
     10 events to clients. In unrelated news, I started a new job this week (which I
     11 love) and they gave me a macbook (which I don't love). Having
     12 :code:`wlr_pointer_gestures_v1` in recent memory and enjoying the macbook's
     13 fancy interactive touchpad gestures, I figured it would be cool to see if such
     14 gestures can be supported by Qtile.
     15 
     16 The result of this weekend project was this pull request:
     17 https://github.com/qtile/qtile/pull/3960.
     18 
     19 At the highest level, this was a two-step process:
     20 
     21 1. Hook up touchpad events in the backend to configurables logic so that users
     22    can create arbitrary bindings to gestures. 'Backend' here meaning the
     23    :code:`libqtile.backend.wayland` module that encapsulates Qtile's
     24    Wayland-specific code.
     25 2. Create user commands for 'sliding' between groups (what Qtile calls
     26    workspaces).
     27 
     28 Both parts enable new functionality, but when combined we can recreate the
     29 interactive touchpad swiping to move between groups.
     30 
     31 Swipe bindings
     32 --------------
     33 
     34 Users create :code:`Drag` objects to define mouse drag bindings. As
     35 :code:`Drag`\s are used for interactive actions such as window moving and
     36 resizing, they have an initial one-shot command to get/set any initial state,
     37 and another command executed upon every movement. This is pretty similar to
     38 what swiping bindings require, so fortunately very little additional code was
     39 needed outside of the backend for the window manager to handle bindings.
     40 
     41 As for the input handling, most of the heavy lifting is done by the
     42 :code:`wlroots` library, specifically its helpers that Qtile uses to set up
     43 devices and receive input events, including multi-touch touchpad gestures.
     44 Consequently, Qtile's swipe bindings are limited to the Wayland backend, and
     45 are not supported under X11.
     46 
     47 For X11, existing standalone tools such as libinput-gestures_ and touchegg_ can
     48 be used for touchpad gestures. They generally work by listening for gesture
     49 events on the device and then when an event of interest is made, they run some
     50 shell command. This unfortunately means that these tools only support one-shot
     51 commands, and not interactive commands. Perhaps it would be possible to create
     52 a CFFI wrapper around libinput in Qtile's X backend to support interactive
     53 gestures, but I suspect this is non-trivial (reach out if you're is interested
     54 in looking into this!).
     55 
     56 Example uses
     57 ------------
     58 
     59 The new :code:`Swipe` class is pretty much the same as :code:`Drag`, except it
     60 needs a number of fingers rather than a button name. This :code:`Drag` example
     61 is lifted from the default config, and below it is the equivalent
     62 :code:`Swipe`, which is demonstrated in the video.
     63 
     64 .. code:: python
     65 
     66     mouse = [
     67         ...
     68 
     69         Drag(
     70             [mod],
     71             "Button1",
     72             lazy.window.set_position_floating(),
     73             start=lazy.window.get_position(),
     74         ),
     75         Swipe(
     76             [mod],
     77             3,  # 3-finger gesture
     78             lazy.window.set_position_floating(),
     79             start=lazy.window.get_position(),
     80         ),
     81     ]
     82 
     83 .. raw:: html
     84 
     85    <video controls width="100%" class="align-center" src="/static/qtile-drag.webm"></video>
     86 
     87 Taking advantage of :code:`LazyCall.when()`, e.g.
     88 :code:`lazy.function(zoom).when(focused=Match(wm_class="firefox"))` would let
     89 you use swipe bindings conditional upon which window is focussed. The X11 tools
     90 mentioned above often have this feature, but this addition to Qtile is the only
     91 way to get even one-shot gesture-bound actions working in Wayland.
     92 
     93 Sliding between groups
     94 ----------------------
     95 
     96 The next step was to add commands to interactively and smoothly 'slide' between
     97 one group and the next/previous. Fundamentally this mechanism is uncoupled from
     98 the gestures mechanism above: if this was added without the ability to have
     99 swipe bindings, one could expect to slide between groups using a mouse dragging
    100 action via the existing :code:`Drag` configurable.
    101 
    102 Indeed, the current (initial) state of the PR does support this, with bindings
    103 for drags and swipes being very similar:
    104 
    105 .. code:: python
    106 
    107     Drag(
    108         [mod, "shift"],
    109         "Button1",
    110         lazy.screen.slide_to_group(),
    111         start=lazy.screen.start_slide_to_group(scale=2.5),
    112     ),
    113     Swipe(
    114         [],
    115         4,
    116         lazy.screen.slide_to_group(),
    117         start=lazy.screen.start_slide_to_group(scale=2.5),
    118     ),
    119 
    120 Here is a poor quality video trying to show how it works. Note that at a few
    121 points I lifted my hands to end the gesture before moving more than half way
    122 towards one of the adjacent workspaces. When that happens, we return to the
    123 start. When the gesture ends, whether we're changing to the next/prev workspace
    124 or returning to the start, there is a smooth animation transitioning the
    125 compositor towards that point:

    133 What's next?
    134 ------------
    135 
    136 The possibility for pinch gestures via a new :code:`Pinch` configurable is low
    137 hanging fruit, though I'm unsure what commands users might bind to them.
    138 Enabling/disabling fullscreening the current window maybe?
    139 
    140 For the workspace animations, these could potentially be one-shot,
    141 non-interactive commands too. This would let users bind to a key press "slide
    142 smoothly to the next workspace", which would be a new feature for those who
    143 don't use trackpads, and indeed some people have already expressed interest in
    144 this.
