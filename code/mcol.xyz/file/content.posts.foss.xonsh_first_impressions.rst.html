      1 xonsh shell: first week, first impressions
      2 ==========================================
      3 
      4 :date: 2019-06-29
      5 :summary: xonsh shell: first week, first impressions
      6 
      7 If you've ever said "Oh boy I wish I could use all that cool pythonic syntax
      8 and algebra in my shell!" then `xonsh <https://github.com/xonsh/xonsh>`_ is
      9 definitely worth checking out.
     10 
     11 For the past week or so I've been using xonsh, a "python-powered,
     12 cross-platform, Unix-gazing shell language and command prompt" as my main
     13 shell. Exploring it has been an adventure and I've learnt much, but after one
     14 week I can tell I've only scratched the surface.
     15 
     16 It is a superset of Python, extending it to include many aspects of shell
     17 syntax and behaviour. This makes for a very powerful yet flexible and usable
     18 language.
     19 
     20 First let me say it is awesome and worth a play if you like Python, but,
     21 unfortunately, it doesn't quite feel as stable as bash or zsh. However, the
     22 `docs <https://xon.sh/>`_ and github issues are fantastic resources to
     23 configure and extend it to be just as (if not more) usable as other shells.
     24 
     25 powerful cli syntax
     26 -------------------
     27 
     28 If you've ever gone from bash to zsh, it was likely a seamless change. In
     29 contrast, the first time playing with xonsh's syntax requires one eye on the
     30 docs. This is understandable, as it was clearly no easy feat creating the
     31 lovechild of bash and python. Check this out:
     32 
     33 .. code-block:: bash
     34 
     35     path = $HOME + '/.xonshrc'
     36     if not !(test -f @(path)):
     37 	return 'Error: %s not found.' % path
     38 
     39 Variables are pythonic; dollar signs are not required, but they prefix
     40 environmental variables by convention. As demonstrated above, we can modify
     41 variables, perform tests and format strings as in python.
     42 
     43 What's cool here are the syntax blocks we see on the second line:
     44 
     45 - :code:`@(...)` treats its contents more like python, so @(path) expands to
     46   the path string.
     47 - :code:`!(...)` treats its contents with a shell syntax. The result from a
     48   :code:`!(...)` block can be used in tests based on its return code, as above,
     49   but the object also contains the standard out and error streams, process id,
     50   and some other information.
     51 
     52 This illustrates a central idea in xonsh: a contextual distinction between
     53 python-like (*python-mode*) and shell-like (*subprocess-mode*) executions.
     54 
     55 xonsh also uses python's logical keywords, which act as drop in replacements
     56 for :code:`&&` and :code:`||`:
     57 
     58 .. code-block:: bash
     59 
     60     a > 10 and echo "a is greater than 10"
     61 
     62 This is only a tiny sample but you get the idea. The shell-like syntax is very
     63 comfortable, and it feels natural to use it alongside python code.
     64 
     65 setup
     66 -----
     67 
     68 Much like zsh, the first time it is run, a wizard will guide you through
     69 initial setup and then get out of the way. This wizard generates your
     70 :code:`~/.xonshrc` file which is run when you launch xonsh.
     71 
     72 The first step is 'Foreign Shell Setup'. This feature aims to help users use
     73 pre-existing bash or zsh configs in xonsh, though currently there are some
     74 limitations. For example, imported aliases that 'cd /some/path' don't seem to
     75 propagate their directory change to the shell. Surfing the github issues it
     76 seems there are a couple of other minor bugs that prevent use of things like
     77 :code:`;` or :code:`&&` in aliases.
     78 
     79 The wizard next helps you set up other useful features and behaviour you see in
     80 other shells:
     81 
     82 - syntax highlighting
     83 - command completion
     84 - vi-mode
     85 - prompts
     86 - plugins
     87 
     88 Most of these are simply controlled by variables set in your :code:`.xonshrc`.
     89 Overall the xonsh initial setup is painless.
     90 
     91 plugins
     92 -------
     93 
     94 xonsh's plugin framework allows for easy extension with xonsh or pure python
     95 scripts called *xontribs*. Some xontribs come pre-packaged but you can download
     96 or create more.
     97 
     98 I was pleased to find that the zsh plugin `z <https://github.com/rupa/z>`_ had
     99 been `ported <https://github.com/astronouth7303/xontrib-z>`_ to xonsh, and a
    100 read of its code makes it clear that porting other zsh plugins would be
    101 relatively straightforward.
    102 
    103 xontribs can do anything you want, such as hooking functions to events, adding
    104 more blocks that can be used in your prompt, adding functional aliases, you
    105 name it.
    106 
    107 For example, we can create new aliases like this:
    108 
    109 .. code-block:: bash
    110 
    111     def _copy(args=None, stdin=None):
    112         """ Copy stdin or args to the clipboard """
    113         text = stdin.read() if stdin else ' '.join(args)
    114         echo -n @(text.strip()) | xclip -selection clipboard
    115         return
    116 
    117     aliases['copy'] = _copy
    118 
    119 Aliases like this send the argument list and stdin to the function as the first
    120 two arguments. This allows us to use shell-like syntax to call the function,
    121 i.e.:
    122 
    123 .. code-block:: bash
    124 
    125     echo 'this will be copied' | copy
    126     copy 'so will this'
    127 
    128 This seems much more natural in a shell.
    129 
    130 Setting up a comfy environment in xonsh has led to me reading all about
    131 `prompt_toolkit <https://github.com/prompt-toolkit/python-prompt-toolkit>`_.
    132 prompt_toolkit is a really powerful python library for controlling what appears
    133 in the terminal window, and does the heavy lifting for xonsh when it comes to
    134 drawing prompts, watching for key bindings, and more. For these reasons, it is
    135 often useful to use its tools directly, rather than xonsh, to extend your xonsh
    136 setup.
    137 
    138 thoughts
    139 --------
    140 
    141 Overall I think xonsh is awesome and I'm excited to see how xonsh develops in
    142 the future. It's a powerful concept, and the motivation appears to be there -
    143 from both core devs and contibuting users - to iron out any issues and improve
    144 the experience.
    145 
    146 It's pretty cool that you can use python libraries as in python:
    147 
    148 .. code-block:: python
    149 
    150     from pykeyboard import PyKeyboard
    151 
    152 Though I haven't actually found a use for that yet!
    153 
    154 It is usable and practical as a daily driver, so I will definitely continue to
    155 use it and see how deep the rabbit hole goes.
