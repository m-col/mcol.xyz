      1 writing a Python wallpaper setter for X11
      2 =========================================
      3 
      4 :date: 2019-11-23
      5 :summary: writing a Python wallpaper setter for X11 
      6 
      7 For the past few weeks I've been learning a lot about the communication
      8 interface between the X11 server and its clients. As a devotee of Qtile_, I
      9 have been using it as a testing ground for a number of tools that directly talk
     10 with the X server, using the Python X bindings provided by xcffib_.
     11 
     12 This exercise has seen me spend a fair bit of time and effort trying to 'port'
     13 C code using XCB_ or xlib_ to xcffib equivalents. At times this is tedious - as
     14 anybody who has written X client code will know - but I like the idea of
     15 extending Qtile to include more features typically outside of the scope of a
     16 standalone window-manager.
     17 
     18 One such feature is the simple ability to set the background wallpaper. Sounds
     19 easy, right? The X server manages the drawing of windows as regions within the
     20 root window, which itself is handled in many ways like a normal window. The
     21 appearance of each window (including the root window) is stored within a
     22 pixmap, whose data can be rendered on-screen as pixels. This description is
     23 super simplified; for a fantastic and more in-depth exploration of how this
     24 works I recommend reading xplain_ by Jasper St. Pierre.
     25 
     26 Setting the desktop wallpaper therefore means colouring and rendering the
     27 pixmap for the root window of each screen. Wrapping this behaviour as an X
     28 client: we need to open a connection to the X server, load our wallpaper image
     29 in a form that can be painted onto a pixmap, and then perform the painting.
     30 I've packaged what I've described here with a convenient interface here_.
     31 
     32 
     33 wallpaper setting with xcffib
     34 -----------------------------
     35 
     36 Opening an X client connection is straightforward and requires the
     37 :code:`DISPLAY` environmental variable. xcffib gives us a :code:`Connection`
     38 object from which we can get information from the X server such as screen
     39 setup.
     40 
     41 .. code-block:: python
     42     
     43     import os
     44     import xcffib
     45     import cairocffi            # needed later
     46     import cairocffi.pixbuf     # needed later
     47     import xcffib.xproto        # needed later
     48 
     49     conn = xcffib.Connection(display=os.environ.get("DISPLAY"))
     50     screens = conn.get_setup().roots
     51 
     52 Next we need to load our image. The cairocffi_ library provides Python bindings
     53 for cairo_, a 2D graphics library that supports rendering graphics to X
     54 pixmaps. We can load our image into what cairo calls a :code:`Surface` with:
     55 
     56 .. code-block:: python
     57 
     58     with open('/path/to/image.png', 'rb') as fd:
     59         image, _ = cairocffi.pixbuf.decode_to_image_surface(fd.read())
     60 
     61 As we need to paint the image to one screen at a time, we could load multiple
     62 images and use a different image for each painting operation.
     63 
     64 The next part performs the painting of the root pixmap to set the wallpaper.
     65 First we must ask the server for a new resource ID and use this to create our
     66 pixmap for the current screen. Creating the pixmap requires the colour depth of
     67 the screen (:code:`screen.root_depth`) as well as its own ID
     68 (:code:`screen.root`), and its dimensions:
     69 
     70 .. code-block:: python
     71 
     72     screen = screens[0]
     73     pixmap = conn.generate_id()
     74     conn.core.CreatePixmap(
     75         screen.root_depth,
     76         pixmap,
     77         screen.root,
     78         screen.width_in_pixels,
     79         screen.height_in_pixels,
     80     )
     81 
     82 We could iterate over :code:`screens` to paint each screen.
     83 
     84 Next we need to extract from the screen its :code:`visual`, which contains
     85 information about how it manages colour maps and depths. We need this to create
     86 a cairo surface that is compatible with the root window, onto which we can
     87 paint our image:
     88 
     89 .. code-block:: python
     90 
     91     for depth in screen.allowed_depths:
     92         for visual in depth.visuals:
     93             if visual.visual_id == screen.root_visual:
     94                 root_visual = visual
     95                 break
     96 
     97     surface = cairocffi.xcb.XCBSurface(
     98         conn, pixmap, root_visual,
     99         screen.width_in_pixels, screen.height_in_pixels,
    100     )
    101 
    102 The cairocffi API for manipulating surfaces provides us a :code:`Context` in
    103 which to modify and use our :code:`Surface` objects (the image and pixmap
    104 surfaces).  Surface manipulation is pretty nice, and it only takes one command
    105 to set our image as a data source and another to paint it to the pixmap:
    106 
    107 .. code-block:: python
    108 
    109     with cairocffi.Context(surface) as context:
    110         context.set_source_surface(image)
    111         context.paint()
    112 
    113 It is at this point where we could add more image manipulations to the source
    114 image before painting, such as stretching or tiling.
    115 
    116 Root windows have two properties named :code:`_XROOTPMAP_ID` and
    117 :code:`ESETROOT_PMAP_ID` which it uses to publish the root pixmap so that other
    118 X clients can have access to the pixel data. This is used for effects such as
    119 the pseudo-transparency feature of urxvt_. We therefore need to set these
    120 properties using our newly painted pixmap.
    121 
    122 The xcffib API for this might look a bit cryptic; we are passing the
    123 property-setting mode :code:`Replace`, the root window concerned, the property
    124 we want to change, the type of data we are passing (:code:`PIXMAP`) and lastly
    125 the bit format, number of items and our list of items (just our pixmap):
    126 
    127 .. code-block:: python
    128 
    129     conn.core.ChangeProperty(
    130         xcffib.xproto.PropMode.Replace,
    131         screen.root,
    132         conn.core.InternAtom(False, 13, '_XROOTPMAP_ID').reply().atom,
    133         xcffib.xproto.Atom.PIXMAP,
    134         32, 1, [pixmap]
    135     )
    136     conn.core.ChangeProperty(
    137         xcffib.xproto.PropMode.Replace,
    138         screen.root,
    139         conn.core.InternAtom(False, 16, 'ESETROOT_PMAP_ID').reply().atom,
    140         xcffib.xproto.Atom.PIXMAP,
    141         32, 1, [pixmap]
    142     )
    143 
    144 We can then change the root window's background pixmap to our pixmap and clear
    145 the area that contains it, which refreshes those pixels to display their new
    146 values:
    147 
    148 .. code-block:: python
    149 
    150     conn.core.ChangeWindowAttributes(
    151         screen.root, xcffib.xproto.CW.BackPixmap, [pixmap]
    152     )
    153     conn.core.ClearArea(
    154         0, screen.root,
    155         0, 0,           # x and y position
    156         screen.width_in_pixels, screen.height_in_pixels
    157     )
    158 
    159 Without the :code:`ClearArea` call background pixels will only refresh when you
    160 move a window over them, which can be a cool effect.
    161 
    162 Lastly we should set our X client's :code:`CloseDown` mode to
    163 :code:`RetainPermanent` to make the our changes to the root window persist
    164 after the client closes, and then disconnect.
    165 
    166 .. code-block:: python
    167 
    168     conn.core.SetCloseDownMode(xcffib.xproto.CloseDown.RetainPermanent)
    169     conn.disconnect()
    170 
    171 The logic we've looked at so far is sufficient to set the X wallpaper, and can
    172 easily be extended to apply wallpapers to multiple screens and to manipulate
    173 our desired image before painting it the pixmap.
    174 
    175 For example, if the dimensions of our image and screen might differ or if we
    176 want to use only a subregion of an image, we can use cairocffi's
    177 :code:`Context` API to change how we paint to our pixmap. The library exposes
    178 :code:`Context.scale()` and :code:`Context.translate()` methods which can be
    179 used right before the paint command to change how the image will map onto the
    180 pixmap.
    181 
    182 
    183 using a solid colour
    184 --------------------
    185 
    186 If we want to paint the wallpaper with a single colour instead of an image, we
    187 can replace the call to :code:`context.set_source_surface()` with the
    188 following, where the three arguments correspond to red, green and blue values:
    189 
    190 .. code-block:: python
    191 
    192     context.set_source_rgb(1, 1, 1) 
    193
