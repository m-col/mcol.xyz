      1 ricing early userspace
      2 ======================
      3 
      4 :date: 2020-06-29
      5 :summary: ricing the TTY
      6 
      7 This weekend I wanted to make the boot process on my Arch Linux machine look
      8 more consistent with the rest of its environment. A while back I configured a
      9 quiet-boot setup to minimise unnecessary steps or messages appearing between
     10 switching on the device and reaching the X11 desktop. The last thing that
     11 remained in making the bootup spotless was the cryptsetup password prompt used
     12 in early userspace to unlock my root partition. It was u g l y.
     13 
     14 After experimenting with plymouth_ and it's various themes (which *do* look
     15 pretty nice), the extra 5 seconds of boot time just isn't acceptable. Like,
     16 come on, I want it to be perfect. I'm a big fan of bitmap fonts and pixel art
     17 so I figured I could hack together some kind of text-based display for the
     18 password prompt using symbols and `box-drawing characters`_.
     19 
     20 Font
     21 ----
     22 
     23 First though, I needed to change the TTY font before reaching that prompt. For
     24 this the `arch wiki`_ had the answer ready so this was a quick job: simply
     25 define :code:`FONT` in :code:`/etc/vconsole.conf` to the name of an available
     26 :code:`psf` font (look inside :code:`/usr/share/kbd/consolefonts` to see
     27 available fonts), then add :code:`consolefont` to the mkinitcpio hooks in
     28 :code:`/etc/mkinitcpio.conf`.
     29 
     30 Drawing the shapes
     31 ------------------
     32 
     33 Looking deeper into `mkinitcpio hooks`_, I discovered that creating your own
     34 hook is actually pretty straight-forward, so I got to work writing one to draw
     35 out the console's display immediately before the password prompt. I simply had
     36 to write a hook to print whatever I wanted and add it to my
     37 :code:`/etc/mkinitcpio.conf`.
     38 
     39 For a simple first-attempt interface, I decided on the message "Welcome" drawn
     40 in big letters in my favourite font, tamzen_, with an input box drawn
     41 underneath for when I'm asked to unlock the root partition. I figured I could
     42 draw the big word by making "pixels" from symbols.
     43 
     44 I got the template by screenshotting my normal xterm (also using the tamzen
     45 font) and scaling it up:
     46 
     47 .. image:: /static/tamzen-Welcome.png
     48    :alt: The word 'Welcome' in tamzen font
     49 
     50 Following this, I typed out a bunch of :code:`echo` commands into my new hook
     51 that would each print a single line of the console, and would together spell
     52 "Welcome" in big letters. For this, I used pairs of block characters (i.e.
     53 "██") as pixels to draw the word pixel-by-pixel. The input box is just an empty
     54 rectangle frame drawn using these pixels underneath the Welcome message. Using
     55 `ANSI escape codes`_ I could move the cursor position into the input box after
     56 printing the display, e.g. printing :code:`"\x1b[32;96H"` will place the cursor
     57 in the 32nd column, 96th row.
     58 
     59 Colours
     60 -------
     61 
     62 Next, I needed to define the colours that all the elements should have: the
     63 background, "Welcome", and the input box. My first instinct was to simply use
     64 more escape codes to set the "current" terminal colour, which would look
     65 something like this:
     66 
     67 .. code-block:: sh
     68     
     69    # This sets the current foreground to colour 0
     70    COLOUR=0
     71    echo -en "\x1b[38;5;${COLOUR}m"
     72 
     73    # While this sets the current background to colour 5
     74    COLOUR=5
     75    echo -en "\x1b[48;5;${COLOUR}m"
     76 
     77 I added lines like these in places in the pixel-drawing echo lines where the
     78 foreground or background colour was to be changed, and it worked quite well.
     79 However, the problem with this is that the colours that the TTY uses are
     80 restricted to default values predefined by the linux framebuffer (which are
     81 *not* pretty).
     82 
     83 A quick search on changing the TTY's colours lead me to `this askubuntu
     84 question`_ describing how to change the colours that correspond to the
     85 consoles's 0-15 colour definitions. Based on these lines (more escape codes!) I
     86 cobbled together some logic at the top of my hook to redefine the TTY's colour
     87 palette using the same hexadecimal colour values I use for my X desktop, and
     88 stripped out the previous escape codes I was using.
     89 
     90 Great! The colours were being set!
     91 
     92 Right as I was planning to put the colour logic into a small package, I came
     93 across Evan Purkhiser's `mkinitcpio-colors`_, which is a more polished version
     94 of what I would have made to set the TTY colours at boot using variables
     95 defined in :code:`/etc/vconsole.conf`. I installed this from the AUR so that my
     96 welcome message would use my usual terminal colour scheme.
     97 
     98 Finishing up
     99 ------------
    100 
    101 The output of fsck is printed out after entering the password. `Apparently`_
    102 this can be silenced, but I preferred to simply reposition the cursor into a
    103 second line of the inpux box so it can be printed there. For this I added a
    104 second hook after the :code:`encrypt` hook.
    105
