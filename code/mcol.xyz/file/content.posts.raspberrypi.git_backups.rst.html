      1 minimal but complete nightly backups to raspberry pi
      2 ====================================================
      3 
      4 :date: 2019-04-25
      5 :summary: minimal but complete nightly backups to raspberry pi
      6 
      7 I searched far and wide for an effective backup solution for my laptop that
      8 wasn't overkill.
      9 
     10 When I first converted to linux I used programs like `timeshift
     11 <https://github.com/teejee2008/timeshift>`_ and `backintime
     12 <https://github.com/bit-team/backintime>`_ and although they worked well, I
     13 wanted more fine grain control over what was backed up and less meat on what
     14 should be a lightweight background process.
     15 
     16 In my quest I stumbled upon this `Hacker News discussion
     17 <https://news.ycombinator.com/item?id=11070797>`_ about turning your home
     18 directory into a git working tree, where its .git folder is in some other
     19 folder, out of the way. This setup stops your home git repo from getting in the
     20 way of any git folders you have in your home directory, but has some problems:
     21 
     22 - you need to remember to use the alias or folder names for this git repo to
     23   use the correct .git folder and working tree
     24 
     25 - working tree changes won't get picked up by utilities like zsh prompts or
     26   ranger, so you might not always remember when things have changed
     27 
     28 - to not pick up every single file in your home directory, these setups
     29   generally ignore untracked files. This requires you to remember to manually
     30   add any new config files in the future
     31 
     32 Maybe I just have a poor memory.
     33 
     34 A slight adjustment of this is to just use the :code:`$HOME/.config` folder for
     35 what it was intended: storing your config files. Turning this folder into your
     36 dotfiles repository, you can treat it as any other git repo.
     37 
     38 Most programs can keep their configs in this folder, but the few that don't can
     39 simply have their configs symlinked into place from the repo. This symlinking
     40 make up the only scripting that would be required to install the repo into
     41 another machine.
     42 
     43 It makes sense to git track configuration files, but your photos, music and
     44 documents? git is not going to like that. This calls for a small bit of
     45 scripting to rsync these folders and push the .config repo to a remote
     46 location.
     47 
     48 First we need the location: a raspberry pi, ticking away somewhere hidden in
     49 your flat, wired to an external hard drive. With one up and running, stick your
     50 hard drive into the pi's :code:`/etc/fstab`:
     51 
     52 .. code-block:: conf
     53 
     54     /dev/disk/by-uuid/1234-abcd /mnt/backups ext4 auto,rw,nofail,noatime,nosuid,noexec 0 0
     55 
     56 Make sure your user has write access to the hard drive and then create the
     57 remote repo for the configs:
     58 
     59 .. code-block:: bash
     60 
     61     mkdir -m 1777 /mnt/backups/dotfiles
     62     cd /mnt/backups/dotfiles
     63     git init --bare
     64 
     65 Make any additional folders for each folder in your home directory that will be
     66 backed up:
     67 
     68 .. code-block:: bash
     69 
     70     mkdir /mnt/backups/{documents,music,pictures}
     71 
     72 While we're on the rasperry pi, let's configure some hard drive power
     73 management so the hard drive spins down soon after the daily backup to save
     74 some power. First install :code:`hdparm`, then set the power management and
     75 spin down settings (see the `Arch wiki
     76 <https://wiki.archlinux.org/index.php/Hdparm#Power_management_configuration>`_
     77 for more info).
     78 
     79 .. code-block:: bash
     80 
     81     apt-get install hdparm
     82     hdparm -B 127 /dev/disk/by-uuid/1234-abcd   # best performance permitting spin-down
     83     hdparm -S 241 /dev/disk/by-uuid/1234-abcd   # spin down after 30 minutes
     84 
     85 Back on the laptop, we write the backup script, substituting where necessary:
     86 
     87 .. code-block:: bash
     88 
     89     pi_IP=192.168.1.2
     90     pi_drive="pi@$pi_IP:/mnt/backups"
     91 
     92     rsyncargs="--recursive --links --times --partial --delete --compress --perms --verbose"
     93     
     94     # this environmental variable lets cron use notify-send for user ID 1000
     95     export DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus
     96     
     97     if ping $pi_IP -c 1 
     98     then
     99         notify-send "Nightly backup to pi" "Backup starting..."
    100     else
    101         notify-send "Nightly backup to pi" "Couldn't ping pi"
    102         exit    # exit if we can't ping the pi - are you still at work?
    103     fi
    104     
    105     {
    106         # dotfiles
    107         git --git-dir=$HOME/.config/.git/ --work-tree=$HOME/.config add -A
    108         git --git-dir=$HOME/.config/.git/ --work-tree=$HOME/.config commit -m "cron commit"
    109         git --git-dir=$HOME/.config/.git/ --work-tree=$HOME/.config push || errors=true
    110     
    111         # other folders
    112         rsync $rsyncargs \
    113     	--exclude=path/to/folder/you/want/to/exclude \
    114     	$HOME/documents/ $pi_drive/documents/ || errors=true
    115     
    116         rsync $rsyncargs $HOME/pictures/    $pi_drive/pictures/  || errors=true
    117         rsync $rsyncargs $HOME/music/       $pi_drive/music/     || errors=true
    118 
    119     # catch the output into a file in case we need it
    120     } | tee -a /tmp/BACKUPLOG-$(date +%y%m%d-%H%M%S)
    121     
    122     # notify with outcome
    123     if ${errors:-false}
    124     then
    125         notify-send "Nightly backup to pi" "Completed with error(s)"
    126     else
    127         notify-send "Nightly backup to pi" "Completed successfully."
    128     fi
    129 
    130 This can easily be run by cron, e.g.:
    131 
    132 .. code-block:: bash
    133 
    134     # backup nightly at 9.30 pm
    135     30 21 * * * $HOME/bin/nightly_backup
    136 
    137 Now every night at 9.30 your home directory will get backed up to the raspberry
    138 pi if you're at home. If it doesn't work for whatever reason, you'll get
    139 notified of the error and you can check out the log in the /tmp folder.
    140 
    141 Complement this with `etckeeper
    142 <https://wiki.archlinux.org/index.php/etckeeper>`_ to back up system files and
    143 this simple and lightweight setup can restore your machine in no time.
